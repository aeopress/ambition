# Hard cases

Use this reference to resolve a difficult choice on the selected axis. Use the result in the rewritten prompt. Do not start the task or add another deliverable.

## Depth or inflation?

Extra work must improve the outcome or the evidence for it. Check each proposed move:

- **Decision:** Name the action that would change because of the move.
- **Raw material:** Reach the original records. More prose from the same summary adds little.
- **Method:** Name a procedure that a practitioner could repeat.
- **Judge:** Require evidence that the ordinary attempt would not provide. An impressive appearance proves nothing.
- **Subtraction:** Replace an artifact when the outcome allows it. Do not retain it and add a second product.
- **Recurrence:** Compare the work removed with the maintenance created.
- **Review:** Keep the result as cheap to check as the original task.

A single tested finding can carry more depth than a large set of charts.

## When to keep the scope

Keep the requested artifact in these cases:

- Someone needs that exact patch, letter, proof or deck. A substitute would break the commitment.
- A broader outcome needs an owner who is unavailable. Keep the rewrite within the user's authority.
- The broader outcome has no observable signal. A claim about later behavior needs evidence.
- The user wants to learn through the work. Preserve their part in it.
- A wrong result could cause serious or irreversible harm, and no check can detect it.
- The task only needs a quick, direct response. Use the Speed branch.

For a retained artifact, raise Depth through original evidence, a stronger method and a check that can reject the result. A required template alone does not force this choice.

## Depth or timidity?

Reject a target that routine competent work already meets. Check for these signs:

- The target repeats the baseline result.
- A requirement, such as correct values, stands in for an ambitious target. Treat it as a veto instead.
- Extra controls, features or pages supply all the claimed ambition.
- The rewrite selects an easy goal and leaves the strong one as an optional stretch.
- Prior evidence shows that the target is easy. Set a harder target in the rewrite.

Use the field's best demonstrated standard. A five-second need may justify a 200 ms target. State the measurement conditions and the constraint that can reject a speed gain.

## How hard targets get faked

A demanding target helps only if a method can reach it and a judge can reject a false result. Watch for these failures:

- A proxy improves while the outcome stays fixed. Warm caches can distort timings. Mocks can hide broken behavior. Leaked test data can inflate prediction scores.
- A plan or an explanation takes the place of a measured result.
- The result meets the number by breaking an unstated constraint. Protect correctness, access, safety and usability with explicit vetoes.
- The rewrite adds bold adjectives but keeps the ordinary method.

For unfamiliar work, make the search for a workable method the first step in the rewrite. Keep the hard target. Outcome pressure without a method can direct attention toward the score instead of the task.

Tell the later execution to keep working past the first result that looks impossible. Require it to report a measured miss honestly. It must disclose any reduction in scope. A claim without a measurement cannot pass. This reference does not authorize execution now.

## What makes a judge independent

A separate process can share the same wrong assumptions. Test the evidence and the ways the judge can fail:

- Give a reviewer the original material before your conclusions. A reviewer who inherits your framing can inherit your errors.
- Check whether tests repeat the implementation's mistaken premise.
- Reserve data for one final check. Repeated tuning on it removes its independence.
- Check that an external benchmark measures the user's outcome.

The judge must be able to reject the result. If every possible observation counts as success, change the check. Another model's agreement alone supplies no external evidence.

## When no judge can exist

For taste, design or prose, specify partial checks in the rewrite:

- **History test:** Fix the signal first. Score it on records excluded from its design.
- **Recorded prediction:** State an expected event and a deadline before checking the result.
- **Source check:** Match each important claim to an original source that supports it.
- **Blind test:** Set criteria first. Compare the proposed result with the ordinary version without revealing which is which.
- **Small sample:** Test a short sample against existing audience feedback or stated preferences. Keep it within the same deliverable.

State which parts remain uncertain. When evidence cannot support a verdict, the rewrite can seek an option map with decisive questions and the strongest objection. Separate observations, inferences and taste. Do not add a question round or switch axes through this reference.

## Four kinds of "can't"

Find the cause before prescribing more effort:

1. **Capability limit:** The approach may exceed what the available model can do. Compare other workable methods.
2. **Missing resource:** Name the absent tool, records or access as setup in the rewrite. Identify what the user must supply. Do not install or request it now.
3. **Missing judge:** Put construction of a check first in the rewrite.
4. **Unclear outcome:** Use the task's stated values. State a conservative assumption when needed. Follow the main skill's triage rule if the axis itself is unclear.

Persistence helps when the limit was underestimated. Missing resources, checks and intent need their own remedies.

## Cost and authority

- Budget the user's review time. Output that nobody can inspect has little practical value.
- A lasting automation needs credentials, monitoring and an owner. Name those prerequisites if the selected Altitude outcome needs it.
- Mark dependencies on decisions outside the user's authority. Do not expand the rewrite into work they cannot authorize.
- For an Altitude replacement, keep the ambitious direction and make the first step disposable. Compare the new way with the current process for one cycle. The current process runs as it does today, outside the rewrite. The rewrite asks for the new way only, never for a second copy of the current artifact. Expand the new way only after an external signal confirms it.

Use these checks within the chosen axis. Finish the rewritten prompt and stop.
