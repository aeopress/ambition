# Documents and presentations

Use this reference for reports, decks, business reviews, proposals, plans, briefs, or spreadsheet work. Use the selected axis only. Put the chosen method in the rewritten prompt. Do not perform the task here.

## Outcome

Name the decision or action that the reader must take. A period update can serve several levels of outcome:

1. Fill the required format with current figures.
2. Explain the causes of the change and their effect on the next action.
3. Frame the few urgent choices. Give evidence that supports and challenges each option.
4. Improve how the team detects trouble or assigns resources. Use past records to test whether the proposed process detects trouble sooner. Compare it with the current process as that process already runs, outside the rewrite. The rewrite asks for the new process only.

When the user asked for the current artifact itself, pick one level. Improve the artifact or replace it. Never ask for both.

Choose an outcome that the user can control. Name the next level without adding it to the scope. Keep an exact artifact when replacing it would break a commitment. A required board, customer, or regulatory template fixes the format alone. It does not rule out Altitude.

## Raw material

Start with records behind the summary. Use product event logs, finance exports, CRM exports, and analytics data. Read verbatim customer comments, support cases, sales records, and meeting transcripts. Prior slides alone cannot establish the cause of a change.

If access is missing, name the exact export in the rewrite's setup. Do not start an access request here.

## Methods and tools

| Weak approach | Method to put in the rewrite |
|---|---|
| A spreadsheet with fixed values | Use formulas, scenario inputs, and sensitivity tables to expose which inputs change the result. |
| A slide full of observations | State one conclusion on each slide. Place its supporting evidence below it. Lead with the decision. |
| A chart drawn from memory | Generate the chart from source records. Label it so a reader can identify its point within five seconds. |
| A familiar explanation accepted as fact | Test that explanation against records. For example, compare onboarding evidence with other causes of churn. |
| A total in a Markdown table | Analyze the records with pandas, SQL, a spreadsheet model, or a notebook. Choose the tool that fits the data. |
| A single mean | Compare segments and cohorts. Inspect trends, confidence intervals, and the matching period in the previous year. |

Use visuals as evidence. A data chart or diagram can replace weak prose within the requested artifact. When the task needs a native file, name `.docx`, `.xlsx`, or `.pptx` and the tool that can produce it. Keep one requested deliverable. Put missing tools in the rewrite's setup.

## Other fields worth borrowing from

- **Forensic accounting:** reconcile headline figures with the original ledger or system records.
- **Information design:** find the chart that communicates the central decision with the least reading.
- **Journalism:** put the new finding first. Trace claims to sources. Include evidence that could overturn the account.
- **Short selling:** use primary records to construct the strongest argument against the proposed plan.
- **Editing:** remove roughly one third of the draft internally. Check which useful content disappears.
- **Audio and motion design:** use a timed or spoken form only when a still image cannot convey the point and the task includes a presentation.

## Judges

- Replay historical periods. Check whether the proposed analysis detects a known problem before the current process does.
- Give the artifact to an unfamiliar member of its intended audience. Check whether that reader can name the decision and supporting evidence within 30 seconds.
- Trace each figure to its record. Reconcile totals with the authoritative system.
- Have an independent reviewer challenge the plan with the original data. Another model's approval alone does not validate it. Require a reproducible contradiction or a source check.

## Targets and vetoes

Set a measurable target that fits the task. Examples include a decision reached after at most ten minutes of reading or an unknown finding that survives a test on unused records. Set a higher target when an ordinary draft already meets the example. Require full source traceability as a correctness veto.

Treat factual accuracy, confidentiality, mandatory branding, required formats, and the speaker's allotted time as vetoes. A strong headline cannot excuse a wrong figure.

## Traps

- Extra slides and an unsolicited dashboard increase scope. Improve the evidence in the artifact already requested.
- Imagined expert personas supply no check. Apply a concrete method to actual records.
- A decorative chart does not support a conclusion.
- A process change can exceed the user's authority. State the needed owner in the rewrite's setup. Do not change the process here.
